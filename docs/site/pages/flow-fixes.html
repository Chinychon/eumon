What it does

Eumon prepares fixes only for repositories whose fingerprint is Next.js with the App Router, and only when the workspace plan includes pull requests. Any other stack gets no fixes. The five fix types are:

  • metadata-base: sets metadataBase in the root layout.
  • head: adds or fixes a page's title and description.
  • jsonld: adds structured data to a page.
  • llms-txt: creates or refreshes public/llms.txt.
  • ai-robots: allows AI search crawlers in public/robots.txt.

Fixes are staged at the end of each analysis. With Autopilot on, Eumon opens at most 3 draft pull requests per run, and never more open Eumon pull requests than the site's PR budget (1 to 5, default 3). Branches are named eumon/<kind>-<route>-<id>.

From draft to merge

  1. A pull request opens as a draft. It leaves draft only after the repository's checks pass.
  2. Eumon then confirms the change in the raw HTML of the preview deploy. If there is no preview, or it is password-protected, Eumon waits 30 minutes and marks the pull request ready on the passing build alone.
  3. A person reviews and merges. Eumon never merges.
  4. Drafts that nobody touched close after 7 days.
  5. After a merge, the next crawl checks the changed pages. If they broke, Eumon opens a revert pull request, but only when the files are unchanged since the merge. Otherwise it asks the user to use GitHub's Revert button.
  6. Rejected and reverted fixes are not proposed again.

The webhook handles check, status, deployment and pull request events as they arrive. A daily sweep from the cron trigger catches any the webhook missed. It handles at most 4 open drafts per run, because of the Free plan's subrequest limits.

What the AI writes

The model only writes words: titles, descriptions and schema field mappings, and only from facts found on the site's own pages. Anything it cannot ground is offered as a copy-paste snippet instead of a change. An analysis makes at most 30 AI calls for fixes (apps/web/src/fix-steps.ts, FIX_AI_CALLS).

What it never does

  • Merge a pull request.
  • Touch a file outside app/**/page.tsx (or src/app/...), the root layout.tsx, components/eumon-json-ld.tsx, public/llms.txt and public/robots.txt.
  • Add a dependency.
  • Allow AI training crawlers. Only OAI-SearchBot, Claude-SearchBot and PerplexityBot are allowed, and only when the site's "Let AI search crawlers read the site" setting is on.
  • Edit a hand-written llms.txt. Eumon creates or refreshes the file only when it carries the line <!-- maintained by Eumon -->.
  • Overwrite components/eumon-json-ld.tsx. It is written only if it does not exist and must match Eumon's version exactly.

GitHub App setup

The administrator of the GitHub App does this once, at github.com/settings/apps/eumon-growth-engine.

  1. Repository permissions. Contents read and write, Pull requests read and write, Checks read, Commit statuses read, Deployments read.
  2. Events. Subscribe to Check run, Check suite, Status, Deployment status and Pull request.
  3. Webhook. Set the URL to https://eumon.chin-gabriel.workers.dev/api/github/webhook and a random secret.
  4. Secret. From apps/web, run npx wrangler secret put GITHUB_WEBHOOK_SECRET and paste the same value. Locally it goes in apps/web/.dev.vars.
  5. Existing installations. Each installation must accept the new permissions before fixes work on its repositories.

Apply migration 0027_fix_engine.sql to the remote database before the deploy that includes the fix engine (see Remote migrations). It adds the fix tables and the per-site settings, including the PR budget.
