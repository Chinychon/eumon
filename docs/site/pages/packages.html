Packages

What each workspace in the monorepo does, what it depends on, what it exports, its main modules and tests, and what to know before changing it. Use it to find where a piece of logic lives.

The npm workspaces are apps/* and packages/* (root package.json). Every package is ESM, named @organic-growth/<name>, written in TypeScript, and compiled by tsc from src/ to dist/. Its package.json points main, types and exports at dist/, so every other workspace, including the web app, imports the built copy, never the source.

CommandWhat it does
npm run build:packagesBuilds every package in dependency order: core, ai, db, repo-analyzer, crawler, scraper, pages, agents, sdk
npm testBuilds the packages, then runs every workspace's test script
npm test -w @organic-growth/<name>One package's tests: tsc -p tsconfig.test.json compiles src (tests included) to dist-test/, then node --test "dist-test/**/*.test.js"
npm run typecheckBuilds the packages, then type-checks every workspace

After changing a package, run npm run build:packages before using it from anywhere else. Until you do, the web app and the other packages' tests keep running the old dist/. npm run dev rebuilds the packages on start (apps/web/scripts/predev.mjs), but a running dev server does not pick up package changes. A single package's npm test -w does not rebuild the packages it depends on either.

Tests use Node's built-in runner (node:test, node:assert/strict); there is no test framework dependency. Tests that need a database use the in-memory SQLite shim from @organic-growth/db/sqlite (Data model: the SQLite test shim).

core

Shared types and pure functions. @organic-growth/core holds the domain types every other workspace uses (SiteRecord, Finding, CrawlPageResult, Dataset, GeneratedPage, PageSettings and the rest in types.ts) and the logic that must give the same answer wherever it runs: the Results math, keyword and backlink views, AI agent classification, WhatsApp reference codes, signed tokens. Nothing in it does I/O, so the API, the client link, the analysis and the tests compute the same numbers.

ai

The language-model client. createLlm returns a JsonLlm that answers a system and user prompt with JSON matching a schema. It picks the provider from the environment: DeepSeek if DEEPSEEK_API_KEY is set, then Claude if ANTHROPIC_API_KEY is set, then the Workers AI binding AI; LLM_MODEL overrides the model. streamChat streams one DeepSeek chat turn with tool calls, for Ask Eumon.

Schemas must list every property in required and set additionalProperties: false; optional values are nullable. Use the schema helpers so a prompt works on every provider. Workers AI does not run locally (Gotchas).

crawler

Fetches and audits a site the way Googlebot sees it: robots.txt, sitemaps, page fetches with the Googlebot user agent, HTML signals (title, canonical, robots, hreflang, JSON-LD, headings, links, text), empty shells and bot challenges, rendering comparisons, and competitor research as EumonBot. It also turns what it measured into findings. HTML is parsed with string scanning in html.ts; there is no DOM library.

isSafePublicUrl (packages/crawler/src/index.ts:26) is the check every user-supplied URL passes: http or https, no credentials, no IP literals, no local or internal names, port 80 or 443. It strips trailing dots first, since localhost. names the same host as localhost. A sitemap file may be up to 25 MB, larger than the cap on a page (Gotchas).

Fetching goes through a Fetcher parameter (default defaultFetcher), so tests and the demo site pass their own. Competitor research identifies itself as RESEARCH_USER_AGENT and never impersonates a search engine.

This package sits at the top of the package graph, so its tests run against the built dist/ of six other packages: rebuild them after changing any of those.

repo-analyzer

Reads a customer's repository through the GitHub API and works out the framework, its routes, and what each route's source says about the HTML it produces (rendering, data fetching, metadata, unbounded queries), plus how the sitemap is generated and which paths are sensitive. Conclusions are inferred from code patterns and carry the evidence.

sdk

A browser tracker for a customer's JavaScript app. createOrganicGrowthTracker({ siteId, endpoint }) returns track(event, { destination }), which posts the event to <endpoint>/<siteId>/events with the page URL and a session id. It reads the landing pages' eumon_sid cookie at send time, so a conversion is credited to the Eumon page the visitor first landed on, and falls back to a session id in sessionStorage. Failures are swallowed so tracking never affects the host app.

Dependencies
@organic-growth/core (type import of ConversionEventName)
Entry
packages/sdk/src/index.ts, the only file; export .

Tests: none; the package has no test script. No workspace imports it. apps/web/README.md documents it as the alternative to the dependency-free tracking script for JavaScript apps. Events land in conversion_events (Data model).

web (apps/web)

@organic-growth/web is the deployed app: a vinext (React Server Components on Vite) app running as a Cloudflare Worker, with the dashboard UI, the API routes, the public landing pages, and the Workflows that run analyses, scrapes and search syncs. It depends on every package except sdk. It is not built to dist/ for other workspaces; it is the consumer. Details are on Web app.
