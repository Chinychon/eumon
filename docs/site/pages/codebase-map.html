How to read it

  • A square is a source file, coloured by workspace. Its size grows with the number of files it uses or is used by. Tests, build output and config files are left out.
  • An arrow means "uses": an import, a call or a re-export from one file to another. Imports of another workspace's built dist/ copy are traced back to the source file that defines the symbol, so apps/web routes point straight at packages/db/src/index.ts.
  • Files that sit close together are tightly linked. Zoom in to read file names. Click a square to list what it uses and what uses it; click a name in that list to jump to it.

Areas

graphify splits the symbol graph into communities: groups of functions, types and modules that call and import each other more than they touch the rest. Each file is listed under the community most of its symbols belong to. The names are graphify's, written from the code, so treat them as a guide to where things live rather than a design.

Regenerating it

/graphify .                 # in Claude Code, at the repo root; writes graphify-out/ (gitignored)
node docs/site/build.mjs    # reduces graphify-out/graph.json into docs/site/codebase-map.json, rebuilds the docs

Commit docs/site/codebase-map.json with the docs, so they build without a local graph. graphify also writes three files worth opening on their own:

graphify-out/graph.html
The full graph at symbol level (functions, types, constants), with search. Open it in a browser.
graphify-out/GRAPH_REPORT.md
The most connected symbols, every community with its members, and links graphify thinks are surprising.
graphify-out/graph.json
The raw graph, for questions like /graphify query "what calls saveCrawlBatch" or /graphify path "ScrapeWorkflow" "D1".
