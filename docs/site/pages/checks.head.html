Checks

Every check the analysis runs, generated from the registry in packages/core/src/checks/catalog.ts, and the checks Eumon deliberately does not run. Each finding names its check with checkId.

Class, severity and the health scores

Each check has a class (error, warning or notice) and one or two pillars (SEO, AI visibility). The class decides whether a failed page counts against the pillar's health score: only error-class page checks do, and only on indexable pages (crawled, not noindex, not canonicalising elsewhere, not a single redirect). Each finding also has a severity, CRITICAL to INFORMATIONAL, from its organic impact score, and severity ranks the growth plan.

The two are separate on purpose. A warning on ten thousand pages is urgent for the plan, but it does not make the site unhealthy. The health score is the share of indexable pages with no error-class issue in the pillar (healthScore in packages/core/src/checks/health.ts). A site-wide error of the pillar, such as robots.txt blocking Googlebot, makes it zero and the tile says why. A firewall that refuses AI search crawlers zeroes the AI score only when it refuses every one that robots.txt allows. Blocking AI crawlers in robots.txt is a choice and never costs score, and llms.txt is reported but never scored.

The page-level error checks behind each score are listed in PAGE_ERROR_CHECKS, and the SQL that counts them is SEO_ERRORS and AI_ERRORS in packages/db/src/index.ts. A test keeps the two in step with the registry.

Adding a check

  1. Register it. Add an entry to packages/core/src/checks/catalog.ts: a dotted id that is never renamed, a short name, pillars, the finding category, class, scope, sources, fix kind, what it needs (requires), the CrawlIssue key when coverage counts it (issue), and the four docs texts. The registry test and this page's build fail on missing docs.
  2. Produce it. Build the finding with finding(CHECKS["…"], { … }), never by hand. A per-page crawl check is a CRAWL_ISSUES condition guarded by a field the crawler always writes, so rows from older crawls are not counted.
  3. Score it, if it is an error on a page. Add it to PAGE_ERROR_CHECKS and to the matching SQL, or to UNSCORED_PAGE_ERRORS with the reason.
