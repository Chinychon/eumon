Eumon overview

What Eumon does, who uses it, and how the monorepo is laid out. Read this first, then follow the pointers at the bottom.

What Eumon is

Eumon is an organic growth engine for small businesses. It has two halves that share one site record, one database and one dashboard.

Site analysis, Results and History

Given only a website URL, Eumon analyses the site the way Google sees it. The analysis Workflow (SiteAnalysisWorkflow, apps/web/src/analysis-workflow.ts) reads the sitemap and robots.txt, fetches every sitemap URL as Googlebot, groups the results by page type, compares the server HTML with what a browser renders, and turns all of that into ranked technical findings and a growth plan of prioritised opportunities. Competitors the operator names are compared by the kinds of pages they publish. When a GitHub repository is connected, Eumon inspects the code per route and can propose fixes as draft pull requests.

Around the analysis sit two longer-running views:

  • Results: numbers synced once a day per site by SearchSyncWorkflow (Search Console, GA4, URL inspection, speed, authority, keywords, and optional connectors such as DataForSEO and Bing). They are stored as one value per site, metric and day in the metric_points ledger. See the sync flow.
  • History: each finished analysis saves the keys of its findings, so the next one can say which problems were resolved, and whether a Eumon change (a merged pull request, a page edit) did it.

The landing-page engine

The core of the product is a programmatic landing-page engine. It breaks a business into the things people search for (doctors, procedures, malls, products), collects structured facts for each, and publishes one crawlable page per unit on the business's own domain:

Scope → Find sources → Collect → Generate → Serve on your domain → Measure → Optimize
  • Scope: an AI analyst reads the site, its sitemap and Search Console queries, and proposes datasets with fields to collect.
  • Collect: ScrapeWorkflow pulls records from the site's own pages, directories, sitemaps, a CSV import, or a Supabase table. The collector identifies as EumonBot and obeys robots.txt.
  • Generate: a template turns each record into a page. The model writes copy patterns once per template, pages are filled from data, and thin or duplicate pages are held back.
  • Serve: complete HTML at /p/:siteId/*, reached through one proxy rule on the customer's site (for example /guides).
  • Measure and optimize: page views, CTA clicks, Googlebot fetches, Search Console data per page, and leads attributed to the page a visitor first landed on.

The full pipeline is on the landing-page flow page.

Who uses it

  • The operator: Eumon's founder, who runs it on their own sites and on client sites as a done-for-you service. They analyse a site, collect its data, publish pages, and watch which pages bring customers.
  • Clients: see their numbers through a read-only client link (/r/<token>), a signed and revocable token that stacks every Results section into one report.

The app has no built-in user accounts. The hostname goes behind Cloudflare Access, with the public paths (/p/*, /api/sites/*/events, /r/*, /api/r/*) excluded (apps/web/README.md).

The running example is medbaycare.com, the operator's own medical-tourism site: one page per doctor, procedure and hospital. A second test case, edeadesign.com.my, is a Drupal site with no client-side JavaScript, used by the collection eval. The engine stays generic: no client's heuristics are hard-coded (apps/web/PRODUCT.md). The first market is Southeast Asian SMBs, where leads usually arrive by WhatsApp or phone.

Monorepo map

An npm workspace (package.json) with one app and nine packages. The packages compile with tsc to dist/, and the web app imports those built copies.

WorkspaceJob
apps/webThe Cloudflare Worker: dashboard, API routes, public landing pages, the client link, and the three Workflows.
packages/coreShared types and pure helpers used by every other package: IDs, signed tokens, metric definitions, trends, text fingerprints, WhatsApp reference codes.
packages/aiOne JSON-output interface over DeepSeek, Claude and Workers AI.
packages/dbD1 queries and the SQL migrations, plus a node:sqlite adapter for tests and the CLIs.
packages/crawlerSitemap discovery, Googlebot crawling, rendering checks and technical SEO findings.
packages/scraperThe scoping analyst, robots.txt-aware collection, structured extraction and CSV import.
packages/pagesPage generation with quality gates, HTML rendering, CTA testing and performance insights.
packages/repo-analyzerStack detection and per-route code inspection of a connected repository.
packages/agentsThe analysis pipeline, growth plan, search and competitor analysis, connector clients (Search Console, GA4, DataForSEO, Bing), pull request generation, and the demo site.
packages/sdkBrowser conversion tracker for JavaScript sites; reads the same eumon_sid cookie as the landing pages.

Outside the workspaces: evals/edea-malls.mjs (collection quality eval) and scripts/audit-site.mjs (site analysis from the command line). Both are covered in Getting started.
